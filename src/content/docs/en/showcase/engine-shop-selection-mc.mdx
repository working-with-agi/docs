import { Aside, Card, CardGrid } from "@astrojs/starlight/components";

Airline engine maintenance planning means deciding, every month, **which engine goes to which shop, when, and with what workscope**. The inputs are scattered: shop quotes, shop manuals, contracts, reliability data, budgets. This showcase shows how to **use the WorkWithAGI SDK to have AI agents run this planning work**, organised by business use case.

The computation itself (stochastic programming, Monte Carlo) is done by the Python scripts in the SDK repository examples. The SDK handles everything around it: **collect the data → agents solve → show results to people for a decision → run again next month**.

<Aside type="caution" title="About the data">
  Every number on this page comes from running the SDK repository example (`examples/engine-shop-selection-mc/`) on **synthetic data** (a 737-800-like fleet: 76 aircraft = 62 mainline + 14 regional, 120–148 required installed positions by month, 166 owned engines, 28.7 shop visits per year in steady state, 45 visits due in the next 24 months; units k$). They are not quotes or actuals from any OEM, shop or airline. Results depend heavily on assumptions — calibrate with real data before use.
</Aside>

## Architecture: which SDK pieces are used

```
 (1) Knowledge                    (2) Agents (sandbox)                      (3) Outputs (GUI layer)
 ─────────────────────────       ─────────────────────────────────         ──────────────────────
 KnowledgeClient                  AgiApiClient.createSession               room.html  decision room
   upload()  quote PDFs, contracts ─► planner : shape data, run scripts ─►   (approvals + deltas + AI Q&A)
   upload()  shop manuals              addPane({ role: "reviewer" })         whatif.html  what-if explorer
   upload()  reliability CSV           reviewer: check assumptions,          (sliders + AI explanation)
   connect() SharePoint / Drive                  contract reading            report.html, compare.html
             (scheduled sync)          parallel: one session per what-if     WorkAGI.terminal embeds
   context() excerpts into prompts     Promise.all([createSession, ...])     the agents' work
                                       baseline: baseline.py freeze/compare
          ▲                                                                          │
          │                                                                          ▼
 (4) Triggers  ─────────────────────────────────────────────────────────────────────────────
   monthly run (1st of the month)  /  meeting-note events (Secretary.io: "E-104 teardown findings")
   /  replaced quotes (knowledge sync)                                    → run (2) again
```

| Piece | Status | Use |
|---|---|---|
| `KnowledgeClient.upload / search / context` | **In the SDK** | Ingest quotes, manuals and reliability data; pass contract terms and TAT excerpts into prompts |
| `KnowledgeClient.connect / sync` (with `schedule`) | **In the SDK** | Periodically sync quote folders on SharePoint, Google Drive, etc. |
| `AgiApiClient.createSession / addPane / destroySession` | **In the SDK** | Start agents in a sandbox, with planner and reviewer role panes |
| `WorkAGI.api / terminal / connect` | **In the SDK** | Create the API client, embed the working terminal in a page, headless connection |
| GUI: decision room (`build_room.py`) | **In the example** | Shared approve / hold / return per decision, deltas from the baseline, AI panel answering from the analysis results |
| GUI: what-if explorer (`build_whatif.py`) | **In the example** | Sliders for uncertain conditions; shows the chosen actions and cost change instantly from precomputed runs, with an AI explanation |
| Report and chooser (`decide.py` / `compare.py`) | **In the example** | Single-file HTML generated inside the sandbox |
| Baseline freeze and deltas (`baseline.py freeze / compare`) | **In the example** | Freeze the annual baseline as JSON with an input fingerprint; solve the (2)–(5) questions in parallel and output a delta table |
| Object storage (versioned plans and inputs) | *Proposed* | Keep each month's plan and assumptions as versions and show "change since last month" |
| Compute job runner | *Proposed* | Run long parallel solves outside the session and notify when done |
| MCP tools (query the plan, write approvals) | *Proposed* | Let the decision room's AI panel and other agents query the plan |
| Scheduled runs, notifications (Slack, calendar), meeting-note events | *Proposed* | Re-plan on a monthly schedule and on Secretary.io meeting notes; notify decision deadlines |

**Known limitations** (gaps in the current SDK found while building the example; S1–S6 in `REQUIREMENTS.md`)

| # | Limitation | Affects |
|---|---|---|
| S1 | The SDK entry point always imports xterm, so Node scripts cannot use it as is (the example bundles with esbuild). A Node entry point is needed | Server-side and scheduled use |
| S2 | Session output and files cannot be read over REST, and follow-up instructions cannot be sent to a running agent | Collecting results, continuing a conversation |
| S3 | `addPane` has no `prompt`, so a second pane (e.g. reviewer) cannot be given instructions | Splitting roles across agents |
| S4 | `WorkAGI` has no entry point to create a `KnowledgeClient` (it is constructed directly) | Consistent developer experience |
| S5 | Sessions and documents cannot carry metadata (only labels and ID naming) | Versioning, linking to the baseline |
| S6 | Sync connector config keys, the `schedule` time zone, how `prompt` is delivered, and overwrite behaviour when uploading with an existing ID are undocumented | Production assumptions |

<Aside type="note" title="TypeScript example">
  The snippets below are simplified from [`examples/engine-mro-agent/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-mro-agent) in the SDK repository (`src/ingest.ts` knowledge ingestion and monthly sync, `src/run-monthly.ts` the monthly planner / reviewer session, `src/ui.ts` the planner's screen). They use only APIs that exist in the current SDK (`@work-with-ai/sdk`).

  ```bash
  npm run ingest -- --pdf-dir ./manuals --drive-folder <FOLDER_ID>   # ingest + monthly sync of the quote folder
  npm run run-monthly -- --month 2026-10                            # start this month's planner + reviewer
  npm run serve                                                     # planner's screen (embedded terminal)
  ```
</Aside>

Common setup (endpoint and key come from the environment):

```typescript
import { KnowledgeClient, WorkAGI } from "@work-with-ai/sdk";

const endpoint = process.env.WORKWITHAI_ENDPOINT!;
const apiKey = process.env.WORKWITHAI_API_KEY!;
const userId = process.env.WORKWITHAI_USER!;

const kb = new KnowledgeClient(process.env.WORKWITHAI_KNOWLEDGE_ENDPOINT ?? endpoint, apiKey);
const api = WorkAGI.api(endpoint, apiKey);
const EXAMPLE = "cd examples/engine-shop-selection-mc && pip install -r requirements.txt";
```

Ingestion (`src/ingest.ts`): document ids are derived from file paths, so re-running replaces the same document. The quote folder is synced monthly.

```typescript
const file = new File([await readFile(path)], basename(path), { type: "application/pdf" });
await kb.upload(file, "engine-mro--pdf-quote-oem-net-pdf");

await kb.connect({
  provider: "google-drive",
  name: "engine-mro shop quotes",
  config: { folder_id: driveFolderId },
  schedule: "0 3 1 * *",            // 1st of every month, 03:00 — just before the monthly re-plan
});
```

## (1) Annual baseline plan (the implicit agreement)

| | |
|---|---|
| **Business question** | In a normal year, how many shop visits, how much spend, how many spares? Everyone agrees on rough numbers when budgeting — we want them with a basis |
| **Who uses it** | Maintenance planning and finance (annual budget), executives (mid-term plan) |

**Flow with the SDK** — put reliability data and shop history into knowledge, have an agent run the 20-year life-cycle simulation to produce the current fleet state, and **freeze the annual baseline as a version**.

```typescript
await kb.upload(reliabilityCsv, "reliability-mtbur");     // unscheduled removal rate, EGT deterioration
await kb.upload(shopHistoryCsv, "shop-visit-history");    // past visits, cost, TAT

const baseline = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "annual-baseline-2026-10",
  prompt: [
    EXAMPLE,
    "python lifecycle.py --fleet-out data/fleet_visits_lifecycle.json",
    "python baseline.py freeze --out baselines/2026-10.json",
    "Run these, then tabulate the baseline's expected cost, cancellation risk, visits, and visits and spend per fiscal year.",
    (await kb.context("unscheduled removal rate, EGT margin deterioration, cost and TAT by workscope", 8)).context,
  ].join("\n"),
});
```

`baseline.py freeze` stores the baseline with a fingerprint of the input data. In later months, `baseline.py compare --baseline baselines/2026-10.json` re-solves the (2)–(5) questions in parallel and outputs a delta table; if the inputs changed after freezing, `compare` warns about it.

**What you get** (synthetic data)

| Item | Baseline (plan of record) |
|---|---|
| Expected total cost | 157,910 k$ |
| Cancellation risk | 0.1% |
| Visits in the next 24 months | 45 |
| By fiscal year | FY2026 12 visits, 79,669 k$ / FY2027 25 visits, 171,480 k$ / FY2028 8 visits, 52,649 k$ |
| Steady state (20-year simulation) | 28.7 visits and 185 M$ per year |

Every other use case is shown as a delta from this baseline.

<Aside type="note">
  Baselines are currently versioned as `baselines/*.json` files. Storing and comparing baselines and monthly plans as versions on the SDK side is part of the object-storage proposal (see also known limitation S5).
</Aside>

**Analysis scripts**: `lifecycle.py`, `baseline.py freeze`

## (2) Monthly induction decisions (do we need to hurry?)

| | |
|---|---|
| **Business question** | Which engines must be decided this month? Which plan do we adopt, and who approves what? |
| **Who uses it** | Maintenance planners (monthly planning meeting), department heads (approval) |

**Flow with the SDK** — the planner pane runs the computation and writes the report, the reviewer checks assumptions, and the work is embedded in the planner's screen.

```typescript
// src/run-monthly.ts (simplified)
const tools = await api.listTools();
if (!tools.claude?.available) throw new Error("claude is not available");

const context = (await Promise.all(
  ["shop TAT delays", "LLP kit lead time", "shop quote revisions and expedite fees",
   "unscheduled engine removals this month"].map((q) => kb.context(q, 5)),
)).map((r) => r.context).join("\n\n");

const month = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "engine-mro-monthly-2026-10",           // the label also prevents a duplicate run for the month
  prompt: plannerPrompt({ month: "2026-10", context }),
  // runs lifecycle → explore → actions → decide → build_room into runs/2026-10/ and writes
  // summary.md (decisions due, approvals, delta from baseline) and review-brief.md
});

await api.addPane(month.session_id, { tool: "claude", role: "reviewer" });
```

The planner's screen (`src/ui.ts`) attaches to the same session to watch the agents and steer them if needed.

```typescript
WorkAGI.terminal({ container: "#terminal", endpoint, apiKey, sessionId: month.session_id, theme: "dark" });
```

<Aside type="note" title="Current SDK limitations">
  `addPane` takes no `prompt`, so the reviewer's instructions are written by the planner to `review-brief.md` and pasted into the pane by a person. There is also no REST call to read a session's outputs, so completion is checked on screen or in `runs/2026-10/summary.md`. Both are listed under "SDK limitations" in the example's README.
</Aside>

**What you get** (delta from baseline, synthetic data, `baseline.py compare`)

| Question | Total cost | Cancellation risk | Visits | Spend by fiscal year | Brought forward |
|---|---:|---:|---:|---|---:|
| External shop TAT +1 month (re-planned) | +205 k$ | −0.1pt | ±0 | FY2027 −9,813 k$ → FY2028 +9,974 k$ | +1 month |

- With congested shops, re-planning keeps total cost almost unchanged but **moves spend from FY2027 to FY2028** — an item for the budget owners, listed in the decision room.
- Engines that must be decided this month, their deadlines, and early-removal exceptions with reasons (watch-list engine, avoiding the peak season, …) are listed in the report and the decision room.

**Analysis scripts**: `compare.py` (seven methods in parallel, chooser page), `decide.py` (report), `baseline.py compare` (deltas), `build_room.py` (decision room)

## (3) Shop and contract selection

| | |
|---|---|
| **Business question** | How many visits go to which of three shops? Are fixed-price contracts, extra slot reservations or an engine-pool membership worth paying for? |
| **Who uses it** | Procurement and contracts, maintenance planners |

**Flow with the SDK** — ingest the quotes; the agent turns each into a "price + risk distribution" JSON. Because this involves contract interpretation, a reviewer pane checks the basis.

```typescript
await kb.upload(inHouseQuotePdf, "quote-in-house");
await kb.upload(oemQuotePdf, "quote-oem-net");
await kb.upload(indMroQuotePdf, "quote-ind-mro");
await kb.upload(overrunHistoryCsv, "findings-overrun-history");

const terms = await kb.context(
  "quoted price, currency, TAT, overrun cost sharing, slot booking lead time, expedite fee, minimum volume per shop", 10);

const shops = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "shop-selection",
  prompt: [
    EXAMPLE,
    "From the excerpts, write my_quotes.json in the format of data/shop_quotes.json; record the basis in notes.md.",
    "Run python run.py --shops my_quotes.json --json-out plan.json and python actions.py, then",
    "summarise visits per shop and the effect of contract actions (fixed price, extra slots, pool).",
    "--- excerpts ---", terms.context,
  ].join("\n"),
});
await api.addPane(shops.session_id, { tool: "claude", role: "reviewer" });
```

**What you get** (delta from baseline, synthetic data)

| Question | Total cost | Cancellation risk | Visits | Spend by fiscal year | Brought forward |
|---|---:|---:|---:|---|---:|
| Asian independent shop at fixed price | +679 k$ | −0.1pt | ±0 | FY2026 +1,893 / FY2027 −1,587 / FY2028 +58 k$ | +7 months |
| Reserve 2 more OEM shop slots | +800 k$ | +0.0pt | ±0 | ±0 | ±0 |
| Engine pool membership | +700 k$ | −0.1pt | ±0 | ±0 | ±0 |

- All three contract actions **cost +679 to +800 k$ and leave cancellation risk essentially unchanged** (the baseline is already at 0.1%). Under base conditions they are insurance only; judge them together with how they perform under the stresses in (5).

<Aside type="caution">
  Reading overrun sharing and slot lead times from quotes involves contract interpretation. Always have procurement or contract staff check the agent's output (`notes.md`).
</Aside>

**Analysis scripts**: `run.py` (re-plan with replaced quotes), `actions.py` (contract actions), `levers.py` (single effect of common levers)

## (4) Asset strategy (spares, mid-life engines, part-out, fleet renewal)

| | |
|---|---|
| **Business question** | Should we buy mid-life engines instead of shop visits? Add spares? As new aircraft arrive, part engines out instead of overhauling them? |
| **Who uses it** | Executives, asset management, fleet planning |

**Flow with the SDK** — sweep the conditions nobody can pin down (used-engine prices, how many aircraft other fleets can lend) and solve each in its own agent session **in parallel**.

```typescript
const whatIfs = {
  explore: "python explore.py --workers 8",          // 5 factors × 108 combinations, classified by decision tree
  breakeven: "python sensitivity.py",                // mid-life price break-even; spare depth × substitution
  transition: "python actions.py",                   // actions incl. the 737-8 delivery case
};
// when all three finish: python build_whatif.py --baseline baselines/2026-10.json builds whatif.html

const sessions = await Promise.all(
  Object.entries(whatIfs).map(([label, cmd]) =>
    api.createSession({
      user_id: userId,
      tool: "claude",
      label: `asset-${label}`,
      prompt: `${EXAMPLE}\n${cmd}\nSummarise in 5 lines the conditions (thresholds) where the answer changes.`,
    })),
);
```

**What you get** (delta from baseline, synthetic data)

| Question | Total cost | Cancellation risk | Visits | Spend by fiscal year |
|---|---:|---:|---:|---|
| Up to 8 mid-life engines available | −10,306 k$ | −0.1pt | −8 (mid-life +8) | FY2026 −10,848 / FY2027 −44,811 / FY2028 +15,360 k$ |
| Two more spare engines | +5,758 k$ | −0.1pt | ±0 | ±0 |
| Part out instead of overhauling | −79,639 k$ | +0.8pt | −14 (part-out +14) | FY2026 −12,414 / FY2027 −86,873 / FY2028 −62,580 k$ |
| Part out while 737-8 deliveries build up | −145,161 k$ | −0.1pt | −26 (part-out +26) | FY2026 −59,087 / FY2027 −169,205 / FY2028 −46,228 k$ |

- Mid-life engines replace 8 shop visits and lower total cost by 10,306 k$, shrinking the FY2027 spending peak (part of it moves to FY2028).
- Parting out cuts cost sharply, but without fleet renewal **cancellation risk rises by 0.8pt**. With 737-8 deliveries building up, 26 visits can be avoided without raising it.
- Two more spares cost +5,758 k$ and do not pay under base conditions.

These conditions can be explored with the sliders in the what-if explorer (`whatif.html`).

**Analysis scripts**: `explore.py`, `sensitivity.py`, `actions.py`, `baseline.py compare`, `build_whatif.py` (what-if explorer)

## (5) Risk response (MRO congestion, LLP shortage)

| | |
|---|---|
| **Business question** | If external shop TAT grows, or LLP kits take 12 months, where does the plan break, and which requirement should we give up? |
| **Who uses it** | Head of maintenance planning, executives (risk meeting), procurement |

**Flow with the SDK** — when "the shops are congested" comes up in a meeting, re-solve the stress cases from that meeting note. Meeting-note events are proposed, so today the agent gets the notes via knowledge search.

```typescript
// Pick relevant remarks from knowledge that syncs Secretary.io meeting notes
const notes = await kb.search("engine shop TAT delay LLP delivery", 5);

const stress = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "risk-backlog",
  prompt: [
    EXAMPLE,
    "Run python decide.py and summarise, for the base, MRO backlog, LLP crunch and combined stress cases,",
    "which requirements can no longer be met and which to give up so the rest hold.",
    "--- meeting notes ---",
    ...notes.results.map((r) => r.chunk),
  ].join("\n"),
});
```

**What you get** (delta from baseline, synthetic data)

| Question | Total cost | Cancellation risk | Spend by fiscal year | Brought forward |
|---|---:|---:|---|---:|
| LLP kit crunch (half the kits on hand, 12-month lead time) | +9,321 k$ | +0.0pt | FY2027 +366 k$ | −1 month |
| LLP crunch, prepared by ordering kits ahead | +9,201 k$ | +0.0pt | FY2027 +366 k$ | −1 month |
| Combined stress (MRO backlog + LLP crunch + more failures) | +11,478 k$ | +0.7pt | FY2026 +7,812 / FY2027 −2,281 / FY2028 −5,054 k$ | +44 months |

- An LLP crunch does not move cancellation risk but **costs +9,321 k$**; ordering kits ahead still leaves +9,201 k$, recovering little.
- Under combined stress, cancellation risk rises by 0.7pt, early removals add up to 44 months and spend shifts into FY2026.

**Analysis scripts**: `baseline.py compare` (deltas), `decide.py` (assumption cases and requirement priority), `actions.py`, `explore.py`

## Appendix: what is computed

Each script is explained in the README of the SDK repository examples.

- [`examples/engine-shop-selection-mc/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-shop-selection-mc) — two-stage stochastic programme treating quotes as price + risk distribution; report, decision room and analysis scripts (Python + PuLP + HiGHS + NumPy)
- [`examples/engine-mro-optimization/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-mro-optimization) — integrated model of removal timing × workscope × spares ([part 1](/en/showcase/engine-mro-optimization/))
- [`examples/engine-mro-agent/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-mro-agent) — the example the TypeScript snippets on this page come from (ingestion, monthly run, UI)

In short, the computation has three steps.

```
1. Monte Carlo   generate N scenarios of quote overruns, TAT delays, FX and unscheduled removals
                 (findings are a property of the engine, so every shop gets the same random draws)
2. Stochastic    stage 1: shop, workscope, induction month and expedite per engine; long-term spares
   programme     stage 2: per scenario × month, fill shortfalls by short-term lease → other type → cancellation
   (SAA)         objective:   min E[total cost] + λ · CVaR90[total cost]   (λ = 0: risk neutral)
                 constraints: fiscal budget, LLP kits, shop slots, minimum volume, spare buffer, risk target
3. Evaluation    mean, P90, CVaR90 and cancellation risk on 5,000 independent scenarios; compare 7 methods
```

The decision deadline is:

```
deadline = planned induction month − longest lead time (shop slot booking, LLP kits not covered by stock)
```
