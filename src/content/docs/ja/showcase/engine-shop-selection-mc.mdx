## 1. 課題: 見積もりは「価格 ＋ リスク分布」

同じワークスコープでも、工場によって契約形態とリスク特性が違います。

| 工場（サンプル） | 契約形態 | `overrun_share` | 特徴 |
|---|---|---:|---|
| `IN-HOUSE` 自社工場 | T&M（実費精算） | 1.0 | 輸送なし・枠 1。findings の超過分は全額自社負担 |
| `OEM-NET` OEM ネットワーク工場 | 固定価格 | 0.0 | 見積もりは高めだが超過なし、遅延も小さい。輸送 1 か月・枠 2 |
| `IND-MRO` 独立系 MRO | 上限付き T&M（50% 負担） | 0.5 | 見積もりは最安だが TAT が長く、混雑遅延のばらつきが大きい |

`overrun_share` は「findings による費用超過のうち自社が負担する割合」で、契約形態を 1 つの数値で表します。T&M なら 1、固定価格なら 0、上限付き T&M や超過分の折半ならその中間です。見積価格の差は、この負担割合と遅延分布を合わせて初めて比較できます。

さらに、工場ごとの判断は互いに独立ではありません。

- 入場が重なる月に複数工場で遅延が同時に起きると、予備エンジンが足りず **AOG**（機体の地上待機）になる。
- その間に **非計画取卸し**（鳥衝突、FOD、ボアスコープ所見など）が起きれば、さらに不足する。
- 予備エンジンを長期リースで事前確保するか、不足時に短期リースで対応するかも、工場選択と一緒に決める必要がある。

### 共通乱数法

findings の有無はエンジンの状態に由来する性質であり、どの工場に出しても同じはずです。そこで同じシナリオでは **全工場に同じ乱数** を使います（共通乱数法）。工場間の違いは「その findings が請求される確率」（`findings.prob`）、「超過率の分布」、「誰が払うか」（`overrun_share`）にだけ現れます。こうすることで、工場比較の差分がサンプリング誤差に埋もれにくくなります。混雑遅延（`delay.shop_*`）は、同じシナリオ内で同じ工場に入った全エンジンに共通にかかります。

## 3. 数理モデル: 二段階確率 MILP

`shop_mc/model.py` の定式化をそのまま記述します。金額は k$、期間は月です。

### 第 1 段と第 2 段

```
第 1 段（今決める、不確実性が明らかになる前）
  x[i] ∈ {0,1}            選択肢 i = (エンジン e, 工場 k, ワークスコープ w, 入場月 t) を採用する
                           t は取卸し可能期間内、w は許容ワークスコープかつ工場 k が見積もったもの
  S    ∈ {0,…,S^max}      計画期間を通じて長期リースする予備エンジン台数

第 2 段（シナリオ s・月 t ごと、費用・遅延・非計画取卸しが判明した後）
  l[s,t] ∈ [0, l^max]     短期リースエンジン数
  a[s,t] ≥ 0              未充足の装着位置数（AOG）
```

以下、紙面上は `x[e,k,w,t]` と書いても `x[i]` と同じものです。

### シナリオが与えるパラメータ

モンテカルロで生成された各シナリオ s は、次を確定させます。

```
cost[s,i]   選択肢 i で自社が負担するショップビジット費
            = price[k,w] + transport_cost[k] + overrun_share[k] · price[k,w] · ρ[s,e,k]
            ρ[s,e,k] = findings が請求された場合の超過率（対数正規）、請求されなければ 0
down[s,i]   選択肢 i の off-wing 月数
            = transport_months[k] + tat[k,w] + shop_delay[s,k] + engine_delay[s,e,k]
A[s,i,t]    = 1  if  t_i ≤ t < t_i + down[s,i]      （月 t に off-wing）
U[s,t]      非計画取卸しで off-wing のエンジン数（ポアソン到着 × 所要月数分布）
```

### 制約

```
(1) 各入場予定はちょうど 1 回計画する
    Σ_{i ∈ I(e)} x[i] = 1                                                ∀ e

(2) 計画上の工場能力（見積 TAT ベース）
    Σ_{i : k_i = k, t_i ≤ t < t_i + tat[k,w_i]} x[i] ≤ slots[k]         ∀ k, t

(3) 装着位置の充足（シナリオ・月ごと）
    owned − Σ_i A[s,i,t] · x[i] − U[s,t] + S + l[s,t] + a[s,t] ≥ D      ∀ s, t
```

(2) は見積 TAT で工場枠を確保する **計画上の** 制約で、輸送や遅延は含みません。遅延による実際の重なりは (3) を通じて予備不足（リース・AOG コスト）として評価されます。

### 目的関数（リスク中立）

```
min  c_S · T · S  −  Σ_i V[w_i] · x[i]                                   第 1 段
     + (1/N) Σ_s Q_s                                                     第 2 段の標本平均

     Q_s = Σ_i cost[s,i] · x[i]  +  Σ_t ( c_l · l[s,t] + c_aog · a[s,t] )
```

`V[w]` は `workscope_build_value`（ワークスコープが計画期間後に残す搭載寿命の価値）で、深いワークスコープほど大きな控除になります。これがないと、24 か月だけ見れば常に最も安い PR が選ばれてしまいます。

### CVaR オプション

`--cvar-weight λ`（λ > 0）を指定すると、目的関数は **総コスト** の期待値と CVaR の和になります。

```
min  E[総コスト] + λ · CVaR_α[総コスト]

総コスト_s = c_S · T · S − Σ_i V[w_i] · x[i]  +  Q_s          （第 1 段の確定項 ＋ シナリオ依存コスト）
```

CVaR は Rockafellar–Uryasev の線形化で表します。

```
min  （上記のリスク中立目的）  +  λ · ( η + 1/((1−α)N) · Σ_s z[s] )
s.t. z[s] ≥ c_S · T · S − Σ_i V[w_i] · x[i] + Q_s − η,   z[s] ≥ 0       ∀ s
     （η は自由変数 = VaR_α の推定値、α は --cvar-alpha、既定 0.9）
```

第 1 段の長期予備費と build value はどのシナリオでも同じ値ですが、CVaR の中に含めることで、長期予備の費用も λ 倍の重みで評価されます。サンプル外評価の CVaR90 と同じ「総コストの CVaR」を最適化していることになります。

### 問題規模（サンプルデータ）

第 1 段の選択肢は 294 個（0-1 変数）＋ 整数 `S`。シナリオ数 N = 200、24 か月で、第 2 段の連続変数が 9,600 個、充足制約が 4,800 本です。

## 4. 計算パイプライン

```
1. モンテカルロ     N 個のシナリオを生成（費用超過・遅延・非計画取卸し）          scenarios.sample
2. SAA              二段階確率 MILP を解く（既定 N = 200）                         model.solve_saa
3. EV 計画          全パラメータを平均値にした確定問題を解く（比較用）            scenarios.mean_value
4. サンプル外評価   独立な大量シナリオ（既定 5,000）で両計画を評価                 evaluate.evaluate
                    → 平均、P50/P90、CVaR90、AOG 確率、VSS = EV − SAA
5. ギャップ推定     M 回の独立 SAA の下界平均と評価値（上界）から最適性ギャップを推定  evaluate.saa_gap
```

**EV 計画** は 20,000 シナリオの平均から作った 1 シナリオの確定問題です（off-wing 月数は整数に丸め、非計画取卸しは小数の定常平均）。「平均値で計画する」従来型の手法に相当し、SAA 計画との差が確率計画にした価値 **VSS**（Value of the Stochastic Solution）になります。

**サンプル外評価** では、第 1 段（x, S）を固定すると第 2 段が次の閉形式になります。

```
shortfall[s,t] = max(0, D − (owned − Σ_i A[s,i,t] x[i] − U[s,t] + S))
l[s,t]         = min(shortfall[s,t], l^max)
a[s,t]         = shortfall[s,t] − l[s,t]
```

MILP を解かずに NumPy のベクトル演算だけで評価できるため、数千シナリオでも数十ミリ秒で終わります。

**最適性ギャップ** は Mak–Morton–Wood 型の推定です。

```
下界  L̄ = (1/M) Σ_m v̂_m        v̂_m: 独立な SAA 問題 m の最適値（ソルバーの dual bound を使用）
上界  Ū = 候補計画のサンプル外平均コスト
gap = Ū − L̄,   95% 片側上限 = gap + 1.645 · sqrt( s_L² / M + s_U² )
```

SAA 最適値の期待値は真の最適値以下になる（下方バイアス）ため `L̄` は統計的な下界、候補計画の評価値は不偏な上界です。各 SAA の値にはソルバーの dual bound を使うので、MIP が完全に解き切れていなくても下界としての妥当性が保たれます。この推定はリスク中立目的にのみ有効で、`--cvar-weight` 指定時はスキップされます。

### モンテカルロは「ソルバー」ではない

本サンプルでは、モンテカルロは **シナリオ生成** と **計画の評価** に使い、計画そのものを探すのは MILP ソルバーです。

- 「候補計画をランダムに作ってシミュレーションし、一番良いものを選ぶ」やり方では、294 個の選択肢と予備台数の組合せ空間をまともに探索できず、最適性の保証もない。
- SAA は、シナリオ全体に対して **1 つの計画** が同時に適応することを MILP で最適化する。入場の重なりと遅延の同時発生のような「裾の相関」が、制約 (3) を通じて直接効く。
- 解いたシナリオと同じシナリオで評価すると楽観的に偏る（最適化バイアス）。そのため、評価は **独立な** シナリオで行い、ギャップ推定で「シナリオ数は足りているか」を確認する。

## 5. 結果例

<Aside type="note" title="合成データによる例">
  合成データ、seed=42、評価 5,000 シナリオ、単位 k$。実在する工場やフリートの実績値ではありません。
</Aside>

| 計画 | 平均 | P90 | CVaR90 | 欠航確率 | 長期予備 |
|---|---:|---:|---:|---:|---:|
| 見積もりどおり（確定） | 38,345 | 43,473 | 46,599 | 47.5% | 0 |
| 期待値（EV、確定） | 36,174 | 39,649 | 42,010 | 14.4% | 1 |
| 悲観値 P90（確定） | 39,687 | 39,950 | 40,466 | **0.5%** | 2 |
| SAA リスク中立 | **35,869** | 38,592 | 40,552 | 7.6% | 1 |
| SAA ＋ CVaR λ=0.3 | 36,074 | 38,471 | 40,168 | 7.6% | 1 |
| SAA ＋ CVaR λ=1（λ=3 も同じ計画） | 36,304 | **38,449** | **39,994** | 6.6% | 1 |

「欠航確率」は、計画期間中に 1 か月でも AOG（装着位置の未充足）が発生するシナリオの割合です。3 つの確定モデルは、それぞれ次の 1 シナリオで解いた計画です。

- **見積もりどおり**: 見積価格・見積 TAT を額面どおりに使い、findings の超過・遅延・非計画取卸しをすべて 0 とする
- **期待値 (EV)**: 20,000 シナリオの平均値
- **悲観値 P90**: 20,000 シナリオの 90 パーセンタイル値（off-wing 月数は切り上げ）

結果から読み取れること:

- 見積もりを額面どおりに信じると、欠航確率が約 5 割になります。見積もりは「価格＋リスク分布」として扱う必要があります。
- 確率計画にした価値（VSS）は **約 305 k$**。平均値だけで計画すると、入場の重なりと遅延の同時発生を過小評価し、欠航確率が約 2 倍になります。
- リスク中立 SAA は、FULL の1件を **固定価格の OEM 工場** に回しています。見積もりは約 1,000 k$ 高いものの、TAT が安定しているため、入場が重なる時期の欠航リスクを下げられます。
- CVaR を加えると平均は数百 k$ 上がり、代わりに P90・CVaR90・欠航確率が下がります（サンプル外評価でも改善）。
- 悲観値計画は欠航をほぼなくしますが、平均で約 3,800 k$ 高くなります。これも「欠航を絶対に避けたい」場合の正当な選択肢で、パレート最適です。
- どれが「正解」かは、コストと欠航リスクをどう天秤にかけるかという経営判断で決まります。次の `compare.py` はその判断を支援します。

## 6. 解き方を並列に比較して選ぶ（`compare.py`）

上表の 7 つの解き方（見積もりどおり、期待値、悲観値 P90、SAA リスク中立、CVaR λ = 0.3 / 1 / 3）を **プロセス並列** で解き、すべての計画を **同じ評価シナリオ**（既定 5,000）で評価します。サンプルでは 4 ワーカーで約 45 秒（逐次なら約 170 秒）です。

```bash
python compare.py                  # 7 手法をプロセス並列で解き、compare.json と compare.html を出力
python compare.py --workers 8
```

| オプション | 既定値 | 内容 |
|---|---|---|
| `--workers N` | CPU コア数 | 並列ワーカー数 |
| `--scenarios N` / `--eval-scenarios N` | `200` / `5000` | SAA に使うシナリオ数 / 共通評価シナリオ数 |
| `--time-limit SEC` | `300` | 各手法の MILP 制限時間 [秒] |
| `--json-out` / `--html-out` | `compare.json` / `compare.html` | 出力先 |
| `--fragment` | — | `<html>`/`<head>` を含まない HTML 断片を出力 |

```
          ┌── 見積もりどおり ──┐
          ├── 期待値 (EV) ─────┤
          ├── 悲観値 P90 ──────┤   ProcessPoolExecutor
 データ ──┼── SAA リスク中立 ──┼── （各ワーカーは HiGHS 1 スレッド）
          ├── CVaR λ=0.3 ──────┤
          ├── CVaR λ=1 ────────┤
          └── CVaR λ=3 ────────┘
                    │
                    ▼
   共通の評価シナリオ 5,000 本で全計画を評価（閉形式リコース）
                    │
                    ▼
   パレート集合の判定 → compare.json ＋ compare.html（選択画面）
```

### パレート集合

各計画を **平均コスト・欠航確率・CVaR90** の 3 指標（すべて小さいほど良い）で比べ、他のどの計画にも 3 指標すべてで負けていない（どれかで同等以下かつどれかで真に劣る計画が存在しない）ものをパレート最適とします。同じ評価シナリオを使うので、指標の差は計画の差そのものです。同一の計画になった手法（例: λ=1 と λ=3）はその旨が表示されます。

### 選択画面（`compare.html`）

外部依存のない 1 ファイルの HTML で、次を表示します。

- **「コストを抑える ↔ 欠航を避ける」スライダー**（「コスト最優先」「バランス」「欠航回避最優先」のプリセット付き）
- コスト × 欠航確率の散布図とパレートフロント
- 選択中の計画の総コスト分布（期待値計画との比較ヒストグラム）と入場スケジュール（工場別の色、期待 off-wing 期間と P90 までの幅）
- 全手法の比較表

スライダーの推奨は次のスコアで決まります。重み w ∈ [0, 1] はスライダー位置（左端 0、右端 1）です。

```
norm(v) = (v − min) / (max − min)        min, max は全候補（7 手法）の中での値

score(m) = (1 − w) · norm(平均コスト_m) + w · norm(欠航確率_m)

推奨 = argmin score(m)   ただし m はパレート最適な計画に限る
```

平均コスト（k$）と欠航確率（%）は単位が違うため、候補の中での相対位置に正規化してから重み付けします。パレート最適でない計画は、どの重みでも推奨されません。表やグラフから直接別の計画を選ぶこともでき、スライダーを動かすと推奨に戻ります。

<Aside type="tip" title="SDK との組み合わせ">
  WorkWithAGI SDK では、エージェントが `createSession` で作られたサンドボックス内で `compare.py` を実行して HTML を生成し、アプリケーションがその選択画面を計画担当者の画面に表示する、という使い方を想定しています。`--fragment` を付けると `<html>`/`<head>` を含まない断片が出力され、既存の画面に埋め込みやすくなります。エージェントは解き方の候補を並べて評価するところまでを担い、**どの計画を採るかは計画担当者がスライダーで重みを決めて選びます**。
</Aside>

## 7. 実行方法

<Steps>

1. 依存パッケージをインストールします（`pulp`, `highspy`, `numpy`）。

   ```bash
   cd examples/engine-shop-selection-mc
   pip install -r requirements.txt
   ```

2. リスク中立 SAA（200 シナリオ）と EV 計画を比較します。

   ```bash
   python run.py
   ```

3. 必要に応じてギャップ推定、リスク回避、独自データを指定します。

   ```bash
   python run.py --replications 5                  # 最適性ギャップの統計推定つき
   python run.py --cvar-weight 1.0                 # リスク回避型
   python run.py --shops my_quotes.json --json-out plan.json
   python -m unittest discover -s tests
   ```

</Steps>

| オプション | 既定値 | 内容 |
|---|---|---|
| `--fleet PATH` | `data/fleet_visits.json` | フリートと入場予定 |
| `--shops PATH` | `data/shop_quotes.json` | 工場見積もりとリスク特性 |
| `--scenarios N` | `200` | SAA に使うシナリオ数 |
| `--eval-scenarios N` | `5000` | サンプル外評価のシナリオ数 |
| `--cvar-weight λ` | `0` | リスク回避の重み（0 = リスク中立） |
| `--cvar-alpha α` | `0.9` | CVaR の信頼水準 |
| `--replications M` | `0` | ギャップ推定用の SAA 反復回数（2 以上で有効） |
| `--seed` | `42` | 乱数シード |
| `--threads N` | — | HiGHS の並列スレッド数 |
| `--time-limit SEC` | `120` | 1 回の MILP の制限時間 [秒] |
| `--json-out PATH` | — | 評価指標、SAA 計画（工場・WS・入場月）、長期予備台数を JSON で保存 |

## 8. 拡張の方向性

| 拡張 | 概要 |
|---|---|
| **第1弾との接続** | [第1弾](/ja/showcase/engine-mro-optimization/) の統合計画の出力を `window` / `allowed_workscopes` / `workscope_build_value` に接続し、「いつ・何を」と「どこで」を階層的に決める |
| **多段階（ローリング）再最適化** | 分解検査後の確定見積もりなど、情報の更新を受けて残りの入場を再最適化する |
| **L-shaped 法（Benders 分解）** | 第 2 段をシナリオごとの部分問題に分け、シナリオ数を大幅に増やす。CVaR の裾推定の改善にも有効 |
| **不確実な工場枠・輸送** | 他社の入場による混雑で工場枠自体を不確実にする、輸送リードタイムを分布として扱う |
