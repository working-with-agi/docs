## 1. 課題: 見積もりは「価格 ＋ リスク分布」

同じワークスコープでも、工場によって契約形態とリスク特性が違います。

| 工場（サンプル） | 契約形態 | `overrun_share` | 通貨 | 特徴 |
|---|---|---:|---|---|
| `IN-HOUSE` 自社工場 | T&M（実費精算） | 1.0 | 本国通貨 | 輸送なし・枠 1・枠予約 1 か月前。findings の超過分は全額自社負担。特急あり |
| `OEM-NET` OEM ネットワーク工場 | 固定価格 | 0.0 | USD | 見積もりは高めだが超過なし、遅延も小さい。輸送 1 か月・枠 2・枠予約 4 か月前。特急あり。最低 2 件の発注契約 |
| `IND-MRO` 独立系 MRO | 上限付き T&M（50% 負担） | 0.5 | USD | 見積もりは最安だが TAT が長く、混雑遅延のばらつきが大きい。枠予約 2 か月前 |

`overrun_share` は「findings による費用超過のうち自社が負担する割合」で、契約形態を 1 つの数値で表します。T&M なら 1、固定価格なら 0、上限付き T&M や超過分の折半ならその中間です。見積価格の差は、この負担割合・遅延分布・為替リスクを合わせて初めて比較できます。

さらに、工場ごとの判断は互いに独立ではありません。

- 入場が重なる月に複数工場で遅延が同時に起きると、予備エンジンが足りず **AOG**（機体の地上待機、欠航）になる。繁忙期ならその損失はさらに大きい。
- その間に **非計画取卸し**（鳥衝突、FOD、ボアスコープ所見など）が起きれば、さらに不足する。
- 予備エンジンを長期リースで事前確保するか、不足時に短期リースで対応するかも、工場選択と一緒に決める必要がある。
- 年度予算、手持ちの LLP キット、工場との最低発注量契約が、選べる組合せを制限する。

### 共通乱数法

findings の有無はエンジンの状態に由来する性質であり、どの工場に出しても同じはずです。そこで同じシナリオでは **全工場に同じ乱数** を使います（共通乱数法）。工場間の違いは「その findings が請求される確率」（`findings.prob`）、「超過率の分布」、「誰が払うか」（`overrun_share`）にだけ現れます。こうすることで、工場比較の差分がサンプリング誤差に埋もれにくくなります。混雑遅延（`delay.shop_*`）は同じシナリオ内で同じ工場に入った全エンジンに共通にかかり、為替は 1 シナリオにつき 1 本の経路をすべての外貨建て見積もりで共有します。

## 2. 急ぐべきか（判断期限）

計画を選ぶ前に、実務でまず問われるのは **「今、決めなければならないエンジンはどれか」** です。`shop_mc/urgency.py` は、ある計画について各エンジンの次の値を出します。

```
判断期限 = 計画上の入場月 − 最も長いリードタイム

  リードタイムの候補
    工場の枠予約       選んだ工場の booking_lead_months
    LLP キット発注     LLP キットを使うワークスコープで、かつ手持ちキットが
                       より早い入場に割り当て済みの場合のみ llp_kits.lead_time_months
                       （手持ちキットは入場月の早い順に割り当てる）

判定
  期限 ≤ 0 か月後  → 「今月決める」
  期限 ≤ 3 か月後  → 「3 か月以内」
  それ以外          → 「待てる」
```

**入場月ごとの期待総コスト曲線** は、そのエンジンだけを取卸し可能期間内の各月に動かし（他のエンジンは固定）、その月で選べる工場・ワークスコープ・特急の中から期待総コストが最小のものを選び直して評価した値です。工場枠・LLP キット・年度予算のどれかを破る選択肢は除外し、その月に選択肢が 1 つも残らなければ **どの制約に阻まれたか**（「工場枠」「LLP キット」「FY2027 予算」など）を記録します。

```
急いだ場合のコスト = 曲線上の最も早い入場可能月の期待総コスト − 計画の期待総コスト
待った場合のコスト = 曲線上の最も遅い入場可能月の期待総コスト − 計画の期待総コスト
```

曲線の評価には共通評価シナリオ（既定 2,000 本、`--urgency-scenarios`）を使います。

サンプルでは、確率計画の場合、E-901・E-902 が「今月決める」、E-904（OEM の枠予約 4 か月）と E-906（LLP キット発注 8 か月）が「3 か月以内」になります。判断期限が先のエンジンは、見積もりの更新や分解検査の結果を待ってから決めても間に合う、ということです。

## 4. 数理モデル: 二段階確率 MILP

`shop_mc/model.py` の定式化をそのまま記述します。金額は k$、期間は月です。

### 第 1 段と第 2 段

```
第 1 段（今決める、不確実性が明らかになる前）
  x[i] ∈ {0,1}            選択肢 i = (エンジン e, 工場 k, ワークスコープ w, 入場月 t, 特急 r) を採用する
                           t は取卸し可能期間内、w は許容ワークスコープかつ工場 k が見積もったもの、
                           r = 特急は工場が特急を提供する場合のみ
  S    ∈ {0,…,S^max}      計画期間を通じて長期リースする予備エンジン台数
  q[k] ≥ 0                工場 k の最低発注量に対する不足件数

第 2 段（シナリオ s・月 t ごと、費用・遅延・非計画取卸しが判明した後）
  l[s,t] ∈ [0, cap_t]     短期リースエンジン数（繁忙期は上限 cap_t = max_engines_peak）
  a[s,t] ≥ 0              未充足の装着位置数（AOG）。コスト c_aog,t は繁忙期に倍率がかかる
```

以下、紙面上は `x[e,k,w,t]` と書いても `x[i]` と同じものです。サンプルの選択肢は 490 個（うち特急 196 個）です。

### シナリオが与えるパラメータ

モンテカルロで生成された各シナリオ s は、次を確定させます。

```
cost[s,i]   選択肢 i で自社が負担するショップビジット費
            = ( price[k,w] · (1 + overrun_share[k] · ρ[s,e,k]) + rush_fee[k]·[r_i] ) · FX[s]^[k は外貨建て]
              + transport_cost[k]
            ρ[s,e,k] = findings が請求された場合の超過率（対数正規）、請求されなければ 0
            FX[s]    = 為替倍率（平均 1、対数正規 σ = fx.volatility）。全外貨建て見積もりで共通
down[s,i]   選択肢 i の off-wing 月数
            = transport_months[k] + TAT_i + shop_delay[s,k] + engine_delay[s,e,k]
            TAT_i = tat[k,w]、特急なら max(1, tat[k,w] − tat_reduction[k])
A[s,i,t]    = 1  if  t_i ≤ t < t_i + down[s,i]      （月 t に off-wing）
U[s,t]      非計画取卸しで off-wing のエンジン数（ポアソン到着 × 所要月数分布）
```

### 第 1 段の固定費

```
F_i = green_time_value · (latest_e − t_i)   −   V[w_i]
      早期取卸しで捨てる寿命                    ワークスコープが生む搭載寿命の価値
```

取卸し期限 `latest` より前に外すと、その月数分の搭載寿命を捨てることになります。`V[w]`（`workscope_build_value`）は深いワークスコープほど大きな控除になり、これがないと 24 か月だけ見れば常に最も安い PR が選ばれてしまいます。

### 制約

```
(1) 各入場予定はちょうど 1 回計画する
    Σ_{i ∈ I(e)} x[i] = 1                                                ∀ e

(2) 計画上の工場能力（見積 TAT、特急なら短縮後の TAT）
    Σ_{i : k_i = k, t_i ≤ t < t_i + TAT_i} x[i] ≤ slots[k]              ∀ k, t

(3) LLP キット: 追加発注が届く前に使えるのは手持ち分だけ
    Σ_{i : w_i ∈ LLP WS, t_i < lead_LLP} x[i] ≤ kits_on_hand

(4) 年度予算（期待整備費を入場月の年度で計上）
    Σ_{i : FY(t_i) = y} Ē[cost_i] · x[i] ≤ budget_y                     ∀ y
    Ē[cost_i] = 最適化に使うシナリオ集合での cost[s,i] の平均

(5) 最低発注量（テイク・オア・ペイ）
    q[k] ≥ min_visits_k − Σ_{i : k_i = k} x[i]                          ∀ k（契約のある工場）

(6) 装着位置の充足（シナリオ・月ごと）
    owned − Σ_i A[s,i,t] · x[i] − U[s,t] + S + l[s,t] + a[s,t] ≥ D      ∀ s, t
```

(2) は見積 TAT で工場枠を確保する **計画上の** 制約で、輸送や遅延は含みません。遅延による実際の重なりは (6) を通じて予備不足（リース・AOG コスト）として評価されます。(4) の予算は期待値に対する制約なので、どの解き方で作ったシナリオ集合を使うかで右辺との関係が変わります（後述の「悲観値 P90」が実行不能になる理由）。

### 目的関数（リスク中立）

```
min  c_S · T · S  +  Σ_i F_i · x[i]  +  Σ_k pen_k · q[k]                  第 1 段
     + (1/N) Σ_s Q_s                                                     第 2 段の標本平均

     Q_s = Σ_i cost[s,i] · x[i]  +  Σ_t ( c_l · l[s,t] + c_aog,t · a[s,t] )
     c_aog,t = aog_cost_per_month · aog_peak_multiplier[暦月(t)]
```

### CVaR オプション

`--cvar-weight λ`（λ > 0）を指定すると、目的関数は **総コスト** の期待値と CVaR の和になります。

```
min  E[総コスト] + λ · CVaR_α[総コスト]

総コスト_s = （第 1 段: c_S·T·S + Σ_i F_i·x[i] + Σ_k pen_k·q[k]）  +  Q_s
```

CVaR は Rockafellar–Uryasev の線形化で表します。

```
min  （上記のリスク中立目的）  +  λ · ( η + 1/((1−α)N) · Σ_s z[s] )
s.t. z[s] ≥ 第 1 段 + Q_s − η,   z[s] ≥ 0                              ∀ s
     （η は自由変数 = VaR_α の推定値、α は --cvar-alpha、既定 0.9）
```

第 1 段の項はどのシナリオでも同じ値ですが、CVaR の中に含めることで λ 倍の重みでも評価されます。サンプル外評価の CVaR90 と同じ「総コストの CVaR」を最適化していることになります。

### 問題規模（サンプルデータ）

第 1 段の選択肢は 490 個（0-1 変数）＋ 整数 `S` ＋ 不足件数 `q`。シナリオ数 N = 200、24 か月で、第 2 段の連続変数が 9,600 個、充足制約が 4,800 本です。

## 5. 計算パイプライン

```
1. モンテカルロ     N 個のシナリオを生成（費用超過・遅延・為替・非計画取卸し）    scenarios.sample
2. SAA              二段階確率 MILP を解く（既定 N = 200）                         model.solve_saa
3. EV 計画          全パラメータを平均値にした確定問題を解く（比較用）            scenarios.mean_value
4. サンプル外評価   独立な大量シナリオ（既定 5,000）で両計画を評価                 evaluate.evaluate
                    → 平均、P50/P90、CVaR90、欠航確率、VSS = EV − SAA
5. ギャップ推定     M 回の独立 SAA の下界平均と評価値（上界）から最適性ギャップを推定  evaluate.saa_gap
6. 判断期限         計画ごとに判断期限と入場月別コスト曲線を算出                   urgency.analyse
```

**EV 計画** は 20,000 シナリオの平均から作った 1 シナリオの確定問題です（off-wing 月数は整数に丸め、非計画取卸しは小数の定常平均）。「平均値で計画する」従来型の手法に相当し、SAA 計画との差が確率計画にした価値 **VSS**（Value of the Stochastic Solution）になります。

**サンプル外評価** では、第 1 段（x, S）を固定すると第 2 段が次の閉形式になります。

```
shortfall[s,t] = max(0, D − (owned − Σ_i A[s,i,t] x[i] − U[s,t] + S))
l[s,t]         = min(shortfall[s,t], cap_t)
a[s,t]         = shortfall[s,t] − l[s,t]
総コスト_s     = 第 1 段（長期予備・F_i・最低発注量の違約金） + Σ_i cost[s,i] x[i]
                 + Σ_t ( c_l · l[s,t] + c_aog,t · a[s,t] )
```

MILP を解かずに NumPy のベクトル演算だけで評価できるため、数千シナリオでも高速です。欠航確率は、計画期間中に 1 か月でも `a[s,t] > 0` となるシナリオの割合です。

**最適性ギャップ** は Mak–Morton–Wood 型の推定です。

```
下界  L̄ = (1/M) Σ_m v̂_m        v̂_m: 独立な SAA 問題 m の最適値（ソルバーの dual bound を使用）
上界  Ū = 候補計画のサンプル外平均コスト
gap = Ū − L̄,   95% 片側上限 = gap + 1.645 · sqrt( s_L² / M + s_U² )
```

SAA 最適値の期待値は真の最適値以下になる（下方バイアス）ため `L̄` は統計的な下界、候補計画の評価値は不偏な上界です。各 SAA の値にはソルバーの dual bound を使うので、MIP が完全に解き切れていなくても下界としての妥当性が保たれます。この推定はリスク中立目的にのみ有効で、`--cvar-weight` 指定時はスキップされます。

### モンテカルロは「ソルバー」ではない

本サンプルでは、モンテカルロは **シナリオ生成** と **計画の評価** に使い、計画そのものを探すのは MILP ソルバーです。

- 「候補計画をランダムに作ってシミュレーションし、一番良いものを選ぶ」やり方では、490 個の選択肢と予備台数の組合せ空間をまともに探索できず、予算や LLP キットの制約を満たす保証も、最適性の保証もない。
- SAA は、シナリオ全体に対して **1 つの計画** が同時に適応することを MILP で最適化する。入場の重なりと遅延の同時発生のような「裾の相関」が、制約 (6) を通じて直接効く。
- 解いたシナリオと同じシナリオで評価すると楽観的に偏る（最適化バイアス）。そのため、評価は **独立な** シナリオで行い、ギャップ推定で「シナリオ数は足りているか」を確認する。

## 6. 結果例

<Aside type="note" title="合成データによる例">
  合成データ、seed=42、評価 5,000 シナリオ、単位 k$（整備で得る搭載寿命価値と早期取卸しで失う寿命を含む純額）。実在する工場やフリートの実績値ではありません。
</Aside>

| 計画 | 平均 | P90 | CVaR90 | 欠航確率 | 今決める |
|---|---:|---:|---:|---:|---:|
| 見積もりどおり（確定） | 34,873 | 42,135 | 45,684 | 20.2% | 2 基 |
| 期待値（EV、確定） | 33,808 | 39,467 | 42,166 | 9.4% | 1 基 |
| 悲観値 P90（確定） | — | — | — | — | 実行不能 |
| SAA リスク中立 | **33,793** | 39,346 | 42,042 | 8.0% | 2 基 |
| SAA ＋ CVaR λ=0.3 | 33,975 | 39,075 | 41,395 | 7.1% | 2 基 |
| SAA ＋ CVaR λ=1（λ=3 も同じ計画） | 34,843 | **38,291** | **40,056** | **5.3%** | 1 基 |

3 つの確定モデルは、それぞれ次の 1 シナリオで解いた計画です。

- **見積もりどおり**: 見積価格・見積 TAT を額面どおりに使い、findings の超過・遅延・非計画取卸しをすべて 0 とする
- **期待値 (EV)**: 20,000 シナリオの平均値
- **悲観値 P90**: 20,000 シナリオの 90 パーセンタイル値（off-wing 月数は切り上げ）

結果から読み取れること:

- 見積もりを額面どおりに信じると、欠航確率は確率計画の約 2.5 倍になります。見積もりは「価格＋リスク分布」として扱う必要があります。
- 悲観値（全コストを P90）で見ると、年度予算・LLP キット・工場枠をすべて満たす計画が存在しません。予算が「平均的にしか」足りていないことを示すシグナルです。
- 確率計画は予算制約のもとで FULL を新年度（4月）に送り、手持ち LLP キット 2 セットを早期の入場に割り当てます。
- CVaR を強めると平均は約 1,000 k$ 上がり、欠航確率は 8.0% → 5.3%、P90・CVaR90 も下がります。
- サンプルの前提（予備エンジン比率 約 10%、繁忙期リース枠 2 台など）が結果を大きく左右します。実データで較正してから使ってください。

<Aside type="caution" title="較正について">
  上の数値は、予備比率・欠航コスト・繁忙期倍率・findings の確率などの合成値に強く依存し、欠航確率の水準や手法間の順位も前提次第で変わります。実運用では、自社の信頼性データ・請求実績・予算で入力を較正したうえで、後述の入力分布パネルで前提が妥当かを確認してください。
</Aside>

## 7. 解き方を並列に比較して選ぶ（`compare.py`）

上表の 7 つの解き方（見積もりどおり、期待値、悲観値 P90、SAA リスク中立、CVaR λ = 0.3 / 1 / 3）を **プロセス並列** で解き、すべての計画を **同じ評価シナリオ**（既定 5,000）で評価し、実行可能だった各計画の判断期限分析も並列で行います（サンプルでは 4 ワーカーで数十秒）。

```bash
python compare.py                  # 7 手法をプロセス並列で解き、compare.json と compare.html を出力
python compare.py --workers 8
```

| オプション | 既定値 | 内容 |
|---|---|---|
| `--workers N` | CPU コア数 | 並列ワーカー数 |
| `--scenarios N` / `--eval-scenarios N` | `200` / `5000` | SAA に使うシナリオ数 / 共通評価シナリオ数 |
| `--urgency-scenarios N` | `2000` | 判断期限のコスト曲線に使うシナリオ数 |
| `--time-limit SEC` | `300` | 各手法の MILP 制限時間 [秒] |
| `--json-out` / `--html-out` | `compare.json` / `compare.html` | 出力先 |
| `--fragment` | — | `<html>`/`<head>` を含まない HTML 断片を出力 |

```
          ┌── 見積もりどおり ──┐
          ├── 期待値 (EV) ─────┤
          ├── 悲観値 P90 ──────┤   ProcessPoolExecutor
 データ ──┼── SAA リスク中立 ──┼── （各ワーカーは HiGHS 1 スレッド）
          ├── CVaR λ=0.3 ──────┤   実行不能な手法はその旨を記録
          ├── CVaR λ=1 ────────┤
          └── CVaR λ=3 ────────┘
                    │
                    ▼
   共通の評価シナリオ 5,000 本で全計画を評価（閉形式リコース）
                    │
                    ▼
   計画ごとの判断期限分析（並列）→ パレート集合 → compare.json ＋ compare.html
```

### パレート集合

実行可能な各計画を **平均コスト・欠航確率・CVaR90** の 3 指標（すべて小さいほど良い）で比べ、他のどの計画にも 3 指標すべてで負けていない（3 指標すべてで同等以下、かつどれかで真に良い計画が存在しない）ものをパレート最適とします。同じ評価シナリオを使うので、指標の差は計画の差そのものです。同一の計画になった手法（例: λ=1 と λ=3）はその旨が表示されます。

### 選択画面（`compare.html`）

外部依存のない 1 ファイルの HTML で、上から順に「急ぐべきか」「どの計画にするか」「会社の制約に収まっているか」「前提にした不確実性は妥当か」を確認できる構成です。

1. **急ぐべきか** — 選択中の計画で今月決めるべきエンジン数、各エンジンの判断期限（効いているリードタイム）、急いだ／待った場合のコスト差、入場月ごとのコスト曲線（繁忙期は網掛け、制約で入場できない月は × と阻んだ制約名）
2. **どの計画にするか** — 「コストを抑える ↔ 欠航を避ける」スライダー（「コスト最優先」「バランス」「欠航回避最優先」のプリセット付き）、コスト × 欠航確率の散布図とパレートフロント、選択中の計画の総コスト分布（期待値計画との比較ヒストグラム）
3. **会社の制約** — 年度別の予算消化率（期待整備費 ÷ 予算）、LLP キット（リードタイム内に使う数 / 手持ち、追加発注数）、最低発注量の達成状況と違約金、早期取卸しで捨てる寿命（月数と金額）、特急件数。あわせて入場スケジュール（工場別の色、期待 off-wing 期間と P90 までの幅、繁忙期と年度境界）
4. **入力パラメータの分布** — 次節
5. **全手法の比較表** — 実行不能だった解き方も表示

スライダーの推奨は次のスコアで決まります。重み w ∈ [0, 1] はスライダー位置（左端 0、右端 1）です。

```
norm(v) = (v − min) / (max − min)        min, max は実行可能な全候補の中での値

score(m) = (1 − w) · norm(平均コスト_m) + w · norm(欠航確率_m)

推奨 = argmin score(m)   ただし m はパレート最適な計画に限る
```

平均コスト（k$）と欠航確率（%）は単位が違うため、候補の中での相対位置に正規化してから重み付けします。パレート最適でない計画は、どの重みでも推奨されません。表やグラフから直接別の計画を選ぶこともでき、スライダーを動かすと推奨に戻ります。

### 入力パラメータの分布パネル

計算に使ったシナリオと同じ乱数モデルから 20,000 回引いた分布を表示し、「見積もりは価格ではなく価格＋この分布として扱っている」ことを計画担当者が確認できるようにします（`scenarios.input_distributions`）。

| パネル | 内容 |
|---|---|
| **見積もり超過（工場別）** | 自社負担分の超過率（`overrun_share` 適用後、見積価格比）。超過なしの割合・平均・P90 と、超過が出た場合のヒストグラム |
| **TAT 遅延（工場別）** | 混雑遅延とエンジン個別遅延を合わせた遅延月数の分布 |
| **為替** | 外貨建て見積もりの本国通貨換算倍率のヒストグラムと P10〜P90 |
| **非計画取卸し** | 24 か月間のフリート全体の発生件数の分布（MTBUR からのポアソン分布）。1 件ごとに 2〜4 か月エンジンが抜ける |
| **欠航コストの季節変動** | 月別の欠航コスト（繁忙期倍率を反映）と、各月の短期リース上限 |

<Aside type="tip" title="SDK との組み合わせ">
  WorkWithAGI SDK では、エージェントが `createSession` で作られたサンドボックス内で `compare.py` を実行して HTML を生成し、アプリケーションがその選択画面を計画担当者の画面に表示する、という使い方を想定しています。`--fragment` を付けると `<html>`/`<head>` を含まない断片が出力され、既存の画面に埋め込みやすくなります。エージェントは解き方の候補を並べて評価するところまでを担い、**いつ決めるか・どの計画を採るかは計画担当者が判断します**。
</Aside>

## 9. 拡張の方向性

| 拡張 | 概要 |
|---|---|
| **第1弾との接続** | [第1弾](/ja/showcase/engine-mro-optimization/) の統合計画の出力を `window` / `allowed_workscopes` / `workscope_build_value` に接続し、「いつ・何を」と「どこで」を階層的に決める |
| **多段階（ローリング）再最適化** | 分解検査後の確定見積もりなど、情報の更新を受けて残りの入場を再最適化する。判断期限の先にあるエンジンは、この再最適化で決めればよい |
| **L-shaped 法（Benders 分解）** | 第 2 段をシナリオごとの部分問題に分け、シナリオ数を大幅に増やす。CVaR の裾推定の改善にも有効 |
| **不確実な工場枠・輸送** | 他社の入場による混雑で工場枠自体を不確実にする、輸送リードタイムを分布として扱う |
