import { Aside, Card, CardGrid } from "@astrojs/starlight/components";

航空会社のエンジン整備計画は、毎月「どのエンジンを、いつ、どの工場に、どこまで直して出すか」を決め続ける仕事です。判断材料は見積書、ショップマニュアル、契約書、信頼性データ、予算と、あちこちに散らばっています。本ショーケースでは、**WorkWithAGI SDK を使って、この計画業務を AI エージェントに回させる** 構成を、業務ユースケースごとに紹介します。

計算そのもの（確率計画・モンテカルロ）は SDK リポジトリのサンプルにある Python スクリプトが担います。SDK が担うのは、その周りの **データを集める → エージェントが解く → 結果を人に見せて判断してもらう → 次の月にまた回す** という流れです。

<Aside type="caution" title="データについて">
  本ページの数値はすべて、SDK リポジトリのサンプル（`examples/engine-shop-selection-mc/`）を **合成データ** で実行した例です（737-800 相当 76 機＝本体 62 ＋ 地域子会社 14、月ごとの必要装着数 120〜148 基、保有 166 基、定常の入場 年 28.7 件、次の 24 か月の入場予定 45 件、単位 k$）。OEM や実在する工場・航空会社の見積もりや実績ではありません。結果は前提に強く依存するため、実データで較正してから使ってください。
</Aside>

## 構成：SDK のどの部品を使うか

```
 ① ナレッジ                       ② エージェント（サンドボックス）          ③ 出力（GUI 層）
 ─────────────────────────       ─────────────────────────────────         ──────────────────────
 KnowledgeClient                  AgiApiClient.createSession               判断ルーム room.html
   upload()  見積書 PDF・契約書   ─►  planner  : データ整形、計算の実行    ─►   （承認共有＋増減＋AI 相談）
   upload()  ショップマニュアル        addPane({ role: "reviewer" })             もしも分析 whatif.html
   upload()  信頼性データ CSV          reviewer : 前提と契約解釈の点検          （スライダー＋AI 説明）
   connect() SharePoint / Drive       並列：what-if ごとに別セッション         報告書 report.html
             （schedule で定期同期）   Promise.all([createSession, ...])        選択画面 compare.html
   context() 抜粋をプロンプトへ       基準：baseline.py freeze / compare       WorkAGI.terminal で
                                                                              作業の様子を埋め込み
          ▲                                                                          │
          │                                                                          ▼
 ④ きっかけ（トリガー）  ─────────────────────────────────────────────────────────────────
   月次の定期実行（毎月 1 日）  ／  会議メモのイベント（Secretary.io で「E-104 の分解所見が出た」）
   ／ 見積書の差し替え（ナレッジ同期）                                   → ② をもう一度回す
```

| 部品 | 状態 | 使い方 |
|---|---|---|
| `KnowledgeClient.upload / search / context` | **SDK にある** | 見積書・マニュアル・信頼性データを取り込み、契約条件や TAT の抜粋をプロンプトに渡す |
| `KnowledgeClient.connect / sync`（`schedule` 付き） | **SDK にある** | SharePoint・Google Drive などの見積書フォルダを定期同期する |
| `AgiApiClient.createSession / addPane / destroySession` | **SDK にある** | サンドボックスでエージェントを起動し、planner と reviewer の役割ペインを並べる |
| `WorkAGI.api / terminal / connect` | **SDK にある** | API クライアントの作成、作業ターミナルの画面埋め込み、ヘッドレス接続 |
| GUI：判断ルーム（`build_room.py`） | **サンプルにある** | 決めるべき項目ごとの承認／保留／差し戻しの共有、基準からの増減、分析結果に答える AI パネル |
| GUI：もしも分析（`build_whatif.py`） | **サンプルにある** | 確定できない条件をスライダーで動かし、事前計算した最適化結果から打ち手とコストの変化を即座に表示、AI が説明 |
| 報告書・選択画面（`decide.py` / `compare.py`） | **サンプルにある** | サンドボックス内で生成する 1 ファイルの HTML |
| 基準の固定と増減（`baseline.py freeze / compare`） | **サンプルにある** | 年間基準を入力の指紋つきで JSON に固定し、②〜⑤ の問いを並列に解いて増減表を出す |
| オブジェクトストレージ（計画と入力の版管理） | *提案* | 月ごとの計画・前提を版として残し、「先月からの差分」を出す |
| 計算ジョブの実行基盤 | *提案* | 数十分かかる並列求解をセッションの外で走らせ、終わったら通知する |
| MCP ツール（計画の照会・承認の書き込み） | *提案* | 判断ルームの AI パネルや他のエージェントから計画を問い合わせる |
| 定期実行・通知（Slack・カレンダー）・会議メモのイベント | *提案* | 月次実行と Secretary.io の会議メモをきっかけに再計算し、判断期限を通知する |

**既知の制約**（例を作る中で見つかった現在の SDK の不足。`REQUIREMENTS.md` の S1〜S6）

| # | 制約 | 影響 |
|---|---|---|
| S1 | SDK の入口が常に xterm を読み込むため、Node のスクリプトからそのまま使えない（実装例は esbuild で束ねて回避）。Node 用の入口が必要 | サーバー側・定期実行からの利用 |
| S2 | セッションの出力やファイルを REST で読めない。実行中のエージェントに追加の指示も送れない | 結果の取り込み、会話の継続 |
| S3 | `addPane` に `prompt` がなく、reviewer などの 2 つ目のペインに指示を渡せない | 複数エージェントの役割分担 |
| S4 | `WorkAGI` に `KnowledgeClient` を作る入口がない（`new KnowledgeClient(...)` で直接作る） | 一貫した使い勝手 |
| S5 | セッションや文書にメタデータを付けられない（ラベルと ID の命名で区別するしかない） | 版管理、基準との対応付け |
| S6 | 同期コネクタの設定キー、`schedule` の時間帯、`prompt` の渡され方、既存 ID でのアップロードの上書き挙動が文書化されていない | 実運用の前提 |

<Aside type="note" title="TypeScript の実装例">
  以下の断片は、SDK リポジトリの [`examples/engine-mro-agent/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-mro-agent) から抜き出して簡略化したものです（`src/ingest.ts` ナレッジ取り込みと月次同期、`src/run-monthly.ts` 月次の planner / reviewer セッション、`src/ui.ts` 計画担当者の画面）。使っているのは現在の SDK（`@work-with-ai/sdk`）にある API だけです。

  ```bash
  npm run ingest -- --pdf-dir ./manuals --drive-folder <FOLDER_ID>   # 取り込み＋見積書フォルダの月次同期
  npm run run-monthly -- --month 2026-10                            # 今月の planner + reviewer を起動
  npm run serve                                                     # 計画担当者の画面（ターミナル埋め込み）
  ```
</Aside>

共通の準備（接続先とキーは環境変数から読みます）:

```typescript
import { KnowledgeClient, WorkAGI } from "@work-with-ai/sdk";

const endpoint = process.env.WORKWITHAI_ENDPOINT!;
const apiKey = process.env.WORKWITHAI_API_KEY!;
const userId = process.env.WORKWITHAI_USER!;

const kb = new KnowledgeClient(process.env.WORKWITHAI_KNOWLEDGE_ENDPOINT ?? endpoint, apiKey);
const api = WorkAGI.api(endpoint, apiKey);
const EXAMPLE = "cd examples/engine-shop-selection-mc && pip install -r requirements.txt";
```

取り込み（`src/ingest.ts`）: 文書 ID をファイルパスから決めるので、再実行しても同じ文書が差し替わるだけです。見積書フォルダは月次の同期にします。

```typescript
const file = new File([await readFile(path)], basename(path), { type: "application/pdf" });
await kb.upload(file, "engine-mro--pdf-quote-oem-net-pdf");

await kb.connect({
  provider: "google-drive",
  name: "engine-mro shop quotes",
  config: { folder_id: driveFolderId },
  schedule: "0 3 1 * *",            // 毎月 1 日 03:00、月次の再計算の直前
});
```

## ① 年間基準計画（暗黙の合意）

| | |
|---|---|
| **業務の問い** | 平常時なら 1 年に何件入場し、いくら使い、予備は何基あれば足りるのか。予算を組むときに皆が「だいたいこのくらい」と合意している数字を、根拠つきで持ちたい |
| **誰が使う** | 整備計画部門・財務（年度予算の策定）、経営層（中期計画） |

**SDK での流れ** — 信頼性データと工場実績をナレッジに入れ、エージェントに 20 年のライフサイクル・シミュレーションを回させて「いまのフリートの状態」を作り、年間基準を **版つきで固定** させます。

```typescript
await kb.upload(reliabilityCsv, "reliability-mtbur");     // 非計画取卸し率・EGT 劣化
await kb.upload(shopHistoryCsv, "shop-visit-history");    // 過去の入場・費用・TAT

const baseline = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "annual-baseline-2026-10",
  prompt: [
    EXAMPLE,
    "python lifecycle.py --fleet-out data/fleet_visits_lifecycle.json",
    "python baseline.py freeze --out baselines/2026-10.json",
    "を実行し、基準の期待総コスト・欠航確率・入場件数・年度別の件数と支出を表にしてください。",
    (await kb.context("非計画取卸し率、EGT マージンの劣化、ワークスコープ別の費用と TAT", 8)).context,
  ].join("\n"),
});
```

`baseline.py freeze` は基準を入力データの指紋つきで保存します。以降の月は `baseline.py compare --baseline baselines/2026-10.json` で ②〜⑤ の問いを並列に解き直し、増減表を出します。基準を固定した後に入力データが変わると、`compare` がその旨を警告します。

**得られるもの**（合成データ）

| 項目 | 基準（計画の正本） |
|---|---|
| 期待総コスト | 157,910 k$ |
| 欠航確率 | 0.1% |
| 次の 24 か月の入場 | 45 件 |
| 年度別 | FY2026 12 件・79,669 k$ ／ FY2027 25 件・171,480 k$ ／ FY2028 8 件・52,649 k$ |
| 定常値（20 年シミュレーション） | 年 28.7 件・1.85 億ドル |

以降のユースケースはすべて、この基準からの増減で示します。

<Aside type="note">
  基準は現在 `baselines/*.json` というファイルで版を管理しています。基準や月ごとの計画を SDK 側で版として保存・比較する仕組みは、オブジェクトストレージの提案に含まれます（既知の制約 S5 も参照）。
</Aside>

**使う分析スクリプト**: `lifecycle.py`、`baseline.py freeze`

## ② 月次の入場判断（急ぐべきか）

| | |
|---|---|
| **業務の問い** | 今月決めなければならないエンジンはどれか。どの計画を採り、誰が何を承認するか |
| **誰が使う** | 整備計画担当者（毎月の計画会議）、部門長（承認） |

**SDK での流れ** — planner が計算と報告書を作り、reviewer が前提を点検し、作業の様子は計画担当者の画面に埋め込みます。

```typescript
// src/run-monthly.ts（簡略化）
const tools = await api.listTools();
if (!tools.claude?.available) throw new Error("claude が使えません");

const context = (await Promise.all(
  ["shop TAT delays", "LLP kit lead time", "shop quote revisions and expedite fees",
   "unscheduled engine removals this month"].map((q) => kb.context(q, 5)),
)).map((r) => r.context).join("\n\n");

const month = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "engine-mro-monthly-2026-10",           // 同じ月の二重起動はラベルで検出して防ぐ
  prompt: plannerPrompt({ month: "2026-10", context }),
  // lifecycle → explore → actions → decide → build_room を runs/2026-10/ に実行し、
  // summary.md（今月決めること・承認事項・基準との差分）と review-brief.md を書く
});

await api.addPane(month.session_id, { tool: "claude", role: "reviewer" });
```

計画担当者の画面（`src/ui.ts`）では、同じセッションに接続して作業を見守り、必要なら指示を足します。

```typescript
WorkAGI.terminal({ container: "#terminal", endpoint, apiKey, sessionId: month.session_id, theme: "dark" });
```

<Aside type="note" title="現在の SDK での注意">
  `addPane` には `prompt` を渡せないため、reviewer への指示は planner が書く `review-brief.md` を担当者がペインに貼り付けます。また REST からセッションの成果物を読む手段がないため、完了は画面か `runs/2026-10/summary.md` で確認します。いずれも実装例の README に「SDK の制約」として整理しています。
</Aside>

**得られるもの**（基準からの増減、合成データ、`baseline.py compare`）

| 問い | 総コスト | 欠航確率 | 入場件数 | 年度別支出 | 前倒し |
|---|---:|---:|---:|---|---:|
| 外部工場の TAT が 1 か月延びたら（再計画） | +205 k$ | −0.1pt | ±0 | FY2027 −9,813 k$ → FY2028 +9,974 k$ | +1 か月 |

- 工場が混んでも、計画し直せば総コストはほぼ変わらず、**支出が FY2027 から FY2028 へ移る** ことが分かります。予算部門との調整事項として判断ルームに並びます。
- 今月決めなければ間に合わないエンジンと判断期限、期限前に取り卸す例外とその理由（要監視エンジン、繁忙期の回避など）が報告書と判断ルームに並びます。

**使う分析スクリプト**: `compare.py`（7 手法の並列比較と選択画面）、`decide.py`（報告書）、`baseline.py compare`（増減）、`build_room.py`（判断ルーム）

## ③ 工場・契約の選定

| | |
|---|---|
| **業務の問い** | 3 社の見積もりのうち、どこに何件出すか。固定価格契約・枠の追加予約・エンジンプール契約は、払う価値があるか |
| **誰が使う** | 調達・契約担当者、整備計画担当者 |

**SDK での流れ** — 見積書を取り込み、エージェントが見積もりを「価格 ＋ リスク分布」の JSON に起こします。契約解釈を含むため、reviewer ペインに根拠を点検させます。

```typescript
await kb.upload(inHouseQuotePdf, "quote-in-house");
await kb.upload(oemQuotePdf, "quote-oem-net");
await kb.upload(indMroQuotePdf, "quote-ind-mro");
await kb.upload(overrunHistoryCsv, "findings-overrun-history");

const terms = await kb.context(
  "各工場の見積価格、通貨、TAT、超過費用の負担条件、枠予約リードタイム、特急料金、最低発注件数", 10);

const shops = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "shop-selection",
  prompt: [
    EXAMPLE,
    "以下の抜粋から data/shop_quotes.json と同じ形式で my_quotes.json を作り、根拠を notes.md に記録。",
    "python run.py --shops my_quotes.json --json-out plan.json と python actions.py を実行し、",
    "工場別の件数と、契約の打ち手（固定価格・枠追加・プール）の効果を要約してください。",
    "--- 抜粋 ---", terms.context,
  ].join("\n"),
});
await api.addPane(shops.session_id, { tool: "claude", role: "reviewer" });
```

**得られるもの**（基準からの増減、合成データ）

| 問い | 総コスト | 欠航確率 | 入場件数 | 年度別支出 | 前倒し |
|---|---:|---:|---:|---|---:|
| アジア独立系を固定価格にしたら | +679 k$ | −0.1pt | ±0 | FY2026 +1,893 ／ FY2027 −1,587 ／ FY2028 +58 k$ | +7 か月 |
| OEM 工場の枠を 2 つ事前確保したら | +800 k$ | +0.0pt | ±0 | ±0 | ±0 |
| エンジン・プール契約を結んだら | +700 k$ | −0.1pt | ±0 | ±0 | ±0 |

- 3 つの契約の打ち手はいずれも **+679〜+800 k$ のコスト増で、欠航確率はほぼ変わりません**（基準が 0.1% と低いため）。基準の条件では「保険」としての価値しかなく、⑤ のストレス下でどう効くかと合わせて判断することになります。

<Aside type="caution">
  見積書から超過費用の負担割合や枠予約リードタイムを読み取る作業は契約解釈を伴います。エージェントの出力（`notes.md`）は必ず調達・契約担当者が確認してください。
</Aside>

**使う分析スクリプト**: `run.py`（見積もりを差し替えた再計算）、`actions.py`（契約の打ち手）、`levers.py`（よく取られる打ち手の単独効果）

## ④ 資産戦略（予備・中寿命エンジン・部品取り・機材更新）

| | |
|---|---|
| **業務の問い** | 工場で直す代わりに中寿命エンジンを買うべきか。予備を増やすべきか。新機種の受領が進むなら、整備せずに部品取りに回すべきか |
| **誰が使う** | 経営層・資産管理部門・機材計画部門 |

**SDK での流れ** — 誰にも確定できない条件（中古エンジンの価格、他機種が肩代わりできる機数など）を振り、条件ごとに別のエージェントセッションで **並列に** 解かせます。

```typescript
const whatIfs = {
  explore: "python explore.py --workers 8",          // 5 条件 × 108 通りで打ち手を選ばせ、決定木で分類
  breakeven: "python sensitivity.py",                // 中寿命エンジン価格の損益分岐、予備の厚さ × 代替運航
  transition: "python actions.py",                   // 737-8 受領が進むケースを含む打ち手の比較
};
// 3 つが終わったら python build_whatif.py --baseline baselines/2026-10.json で whatif.html を作る

const sessions = await Promise.all(
  Object.entries(whatIfs).map(([label, cmd]) =>
    api.createSession({
      user_id: userId,
      tool: "claude",
      label: `asset-${label}`,
      prompt: `${EXAMPLE}\n${cmd}\n結果から、答えが切り替わる条件（しきい値）を 5 行で要約してください。`,
    })),
);
```

**得られるもの**（基準からの増減、合成データ）

| 問い | 総コスト | 欠航確率 | 入場件数 | 年度別支出 |
|---|---:|---:|---:|---|
| 中寿命エンジンを最大 8 基使えたら | −10,306 k$ | −0.1pt | −8（中寿命 +8） | FY2026 −10,848 ／ FY2027 −44,811 ／ FY2028 +15,360 k$ |
| 予備エンジンを 2 基増やしたら | +5,758 k$ | −0.1pt | ±0 | ±0 |
| 整備せず部品取りで打ち切れるなら | −79,639 k$ | +0.8pt | −14（部品取り +14） | FY2026 −12,414 ／ FY2027 −86,873 ／ FY2028 −62,580 k$ |
| 737-8 の受領が進む中で部品取りを使うなら | −145,161 k$ | −0.1pt | −26（部品取り +26） | FY2026 −59,087 ／ FY2027 −169,205 ／ FY2028 −46,228 k$ |

- 中寿命エンジンは工場整備 8 件を置き換えて総コストが −10,306 k$ 下がり、FY2027 の支出の山が小さくなります（一部は FY2028 に移る）。
- 部品取りは大きくコストを下げますが、機材更新がないと **欠航確率が +0.8pt** 上がります。737-8 の受領が進むなら欠航確率を上げずに 26 件を打ち切れます。
- 予備の追加は +5,758 k$ で、基準の条件では割に合いません。

これらの条件は「もしも分析」画面（`whatif.html`）のスライダーで動かして見られます。

**使う分析スクリプト**: `explore.py`、`sensitivity.py`、`actions.py`、`baseline.py compare`、`build_whatif.py`（もしも分析画面）

## ⑤ リスク対応（MRO 混雑・LLP 逼迫）

| | |
|---|---|
| **業務の問い** | 外部工場の TAT が延びたら、LLP キットの調達が 12 か月になったら、計画はどこが崩れ、どの要望を諦めればよいか |
| **誰が使う** | 整備計画部門長・経営層（リスク会議）、調達部門 |

**SDK での流れ** — 会議で「工場が混んでいる」と話題に出たら、その会議メモをきっかけにストレスケースを解き直します。会議メモからのイベント連携は提案段階なので、現在はナレッジ検索で拾った議事メモをプロンプトに渡します。

```typescript
// Secretary.io の議事メモを同期しているナレッジから、関連する発言を拾う
const notes = await kb.search("エンジン工場 TAT 遅延 LLP 納期", 5);

const stress = await api.createSession({
  user_id: userId,
  tool: "claude",
  label: "risk-backlog",
  prompt: [
    EXAMPLE,
    "python decide.py を実行し、基準・MRO 混雑・LLP 逼迫・複合ストレスの 4 ケースで",
    "どの要望が満たせなくなるか、どれを諦めれば残りが守れるかを要約してください。",
    "--- 会議メモ ---",
    ...notes.results.map((r) => r.chunk),
  ].join("\n"),
});
```

**得られるもの**（基準からの増減、合成データ）

| 問い | 総コスト | 欠航確率 | 年度別支出 | 前倒し |
|---|---:|---:|---|---:|
| LLP キットが逼迫したら（手持ち半減・調達 12 か月） | +9,321 k$ | +0.0pt | FY2027 +366 k$ | −1 か月 |
| LLP 逼迫にキット先行発注で備えたら | +9,201 k$ | +0.0pt | FY2027 +366 k$ | −1 か月 |
| 複合ストレス（MRO 混雑＋LLP 逼迫＋故障増） | +11,478 k$ | +0.7pt | FY2026 +7,812 ／ FY2027 −2,281 ／ FY2028 −5,054 k$ | +44 か月 |

- LLP 逼迫は欠航確率には効かず、**コストで +9,321 k$** 効きます。キットの先行発注で備えても +9,201 k$ で、ほとんど取り戻せません。
- 複合ストレスでは欠航確率が +0.7pt 上がり、前倒しが合計 44 か月に増えて支出が FY2026 に寄ります。

**使う分析スクリプト**: `baseline.py compare`（増減）、`decide.py`（前提ケースと要望の優先順位）、`actions.py`、`explore.py`

## 付録：計算の中身

各スクリプトの中身は、SDK リポジトリのサンプルに README として説明があります。

- [`examples/engine-shop-selection-mc/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-shop-selection-mc) — 工場見積もりを価格 ＋ リスク分布として扱う二段階確率計画、報告書・判断ルーム・分析スクリプト一式（Python + PuLP + HiGHS + NumPy）
- [`examples/engine-mro-optimization/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-mro-optimization) — 取卸し時期 × ワークスコープ × 予備エンジンの統合計画モデル（[第1弾](/ja/showcase/engine-mro-optimization/)）
- [`examples/engine-mro-agent/`](https://github.com/working-with-agi/sdk/tree/claude/aircraft-engine-repair-optimization-8oww5m/examples/engine-mro-agent) — 本ページの TypeScript 断片の元になった実装例（取り込み・月次実行・画面）

要点だけ示すと、計算は次の 3 段です。

```
1. モンテカルロ   見積もりの費用超過・TAT 遅延・為替・非計画取卸しのシナリオを N 本生成
                  （不具合の有無はエンジン側の性質なので、同じシナリオでは全工場に同じ乱数）
2. 確率計画(SAA)  1 段目: 各エンジンの工場・ワークスコープ・入場月・特急、長期予備の台数
                  2 段目: シナリオ × 月ごとに、不足を 短期リース → 別機種で代替 → 欠航 の順に埋める
                  目的:   min E[総コスト] + λ · CVaR90[総コスト]   （λ = 0 ならリスク中立）
                  制約:   年度予算、LLP キット、工場枠、最低発注量、予備バッファ、欠航確率目標
3. 評価           独立な 5,000 シナリオで平均・P90・CVaR90・欠航確率を出し、7 つの解き方を比べる
```

判断期限は次の式で出します。

```
判断期限 = 計画上の入場月 − 最も長いリードタイム（工場の枠予約、手持ちで足りない LLP キットの発注）
```
