## 2つのパラダイム

AI による業務支援には、大きく分けて2つのアプローチがあります。

<CardGrid>
  <Card title="Cowork — チャットベース支援" icon="comment">
    ユーザーが質問し、AI が回答する。

    - 「この議事録をまとめて」
    - 「先週の会議で決まったことは？」
    - 「次のミーティングのアジェンダを作って」

    **人間が起点**。AI は聞かれたことに答える。
  </Card>
  <Card title="Secretary — 自律支援" icon="rocket">
    AI が自ら動き、人間は結果を受け取る。

    - 会議に自動参加し、録音・文字起こし
    - 議事録を要約し、アクションアイテムを抽出
    - タスクの進捗を追跡し、リマインドを送信

    **AI が起点**。人間は確認と意思決定に集中する。
  </Card>
</CardGrid>

## Cowork の限界

チャットベースの AI 支援は強力ですが、組織が成長するにつれて限界が見えてきます。

| 課題 | Cowork の現実 |
|---|---|
| **情報の散逸** | 会議の内容は参加者の記憶とメモに依存。聞き逃し、記録漏れが常態化 |
| **受動的** | ユーザーが適切な質問をしなければ、AI は何も返さない |
| **コンテキスト不足** | 会議に参加していない AI は、議論の文脈を持たない |
| **スケールしない** | 会議が増えるほど、人間が AI に伝える手間も増える |

Cowork は「AI に仕事を頼む」モデル。頼む側の負担がボトルネックになります。

---

## Secretary が解決すること

Secretary は「AI が仕事を引き受ける」モデルです。

```
Cowork:    人間 → 質問 → AI → 回答 → 人間が整理
Secretary: AI → 会議参加 → 録音 → 文字起こし → 要約 → アクション抽出 → 人間が確認
```

<CardGrid>
  <Card title="自動的にコンテキストを獲得" icon="seti:audio">
    Bot が会議に参加し、リアルタイムで音声をキャプチャ。人間が伝える必要がない。
  </Card>
  <Card title="構造化された知識に変換" icon="document">
    録音データを文字起こしし、要約・アクションアイテム・意思決定を自動抽出。
  </Card>
  <Card title="プロジェクト横断で追跡" icon="list-format">
    複数の会議・プロジェクトにまたがるタスクと決定事項を一元管理。
  </Card>
  <Card title="先回りして通知" icon="warning">
    期限切れのアクションアイテム、放置された議題、リスクの兆候を検知してアラート。
  </Card>
</CardGrid>

## Cowork + Secretary

Cowork と Secretary は排他的ではありません。Secretary が自律的に収集・整理した情報に対して、Cowork（チャット）でさらに深掘りする — これが最も効果的な使い方です。

```
┌──────────────────────────────────────────────────┐
│                Secretary (自律層)                  │
│                                                    │
│   会議参加 → 録音 → 文字起こし → 要約 → 蓄積      │
│                         │                          │
│                    KnowledgeHub                     │
│                         │                          │
├──────────────────────────┼─────────────────────────┤
│                Cowork (対話層)                      │
│                         │                          │
│   「先週の会議で田中さんが言ったリスクって何？」     │
│   「Q3のOKR進捗をプロジェクト横断でまとめて」       │
│   「この決定の背景を教えて」                        │
│                                                    │
└──────────────────────────────────────────────────┘
```

Secretary が**情報を集め**、Cowork が**情報を引き出す**。人間は「何を聞くべきか」を考えることだけに集中できます。

<Aside type="tip" title="PMO を雇えない組織のために">
5〜30名規模の組織では、専任の PMO を置く余裕がないことが多い。Secretary は、その PMO の役割 — 会議の記録、決定事項の追跡、進捗の可視化 — を AI が自律的に担います。
</Aside>

## Secretary.IO での実装

[Secretary.IO](/showcase/secretary-io/) は、この Cowork to Secretary のコンセプトを具現化したプロダクトです。

| 機能 | パラダイム | 説明 |
|---|---|---|
| 会議 Bot（Vexa） | Secretary | Google Meet / Zoom / Teams に自動参加し録音 |
| リアルタイム文字起こし | Secretary | 音声を即座にテキスト化 |
| AI 議事録 | Secretary | 要約・アクションアイテム・決定事項を自動生成 |
| Noah（AI アシスタント） | Cowork | チャットで会議データを横断検索・質問応答 |
| MAGI 分析 | Secretary + Cowork | 複数視点からの自律分析 + 対話的な深掘り |
| プロジェクト管理連携 | Secretary | Linear / Jira へのタスク自動起票 |
